02 How RN Differs from Flutter

Understanding the difference between the Flutter and RN SDKs explains why the architecture looks the way it does.

Flutter
Bridge: MethodChannel (request/response)
Stream: EventChannel (native push)
Subscription: CampaignsStreamMixin
Replay: StateFlow → EventChannel (auto)
UI Host: Widget tree
React Native
Bridge: NativeModules (@ReactMethod)
Stream: DeviceEventEmitter (native push)
Subscription: NativeEventEmitter in useCampaigns
Replay: getScreenCampaigns triggers re-emit

Android (Compose)
Bridge: Direct Kotlin call
Stream: collectAsState()
Subscription: Compose state collection
Replay: StateFlow native replay
UI Host: overlayElements() composable

The NativeModules Bridge

Flutter uses MethodChannel — a typed, named bridge. React Native uses NativeModules, which exposes any method annotated with @ReactMethod as a JavaScript-callable function that returns a Promise.

Kotlin — @ReactMethod (equivalent to Flutter MethodChannel handler)
@ReactMethod
fun getUserId(promise: Promise) {
    promise.resolve(core.userId)   // Promise = Flutter's result.success()
}
TypeScript — NativeModules call (equivalent to Flutter MethodChannel.invokeMethod)
const { AppStorysReactNative } = NativeModules;
const userId: string = await AppStorysReactNative.getUserId();
// Equivalent Flutter: await platform.invokeMethod('getUserId')

Why No overlayElements()

Android wraps all campaign UI in an overlayElements() composable placed outside the NavHost so floating campaigns always render above all screens. React Native doesn't need this — you place components (<Floater>, <Modal>, etc.) inside your screen JSX directly. The component returns null when no campaign is active so it has zero cost when hidden.

03 EventEmitter Pipeline

This is the most important architectural concept in the RN SDK. The EventEmitter pipeline is the equivalent of Flutter's EventChannel → campaignsStream and it replaced the original 1500ms polling hack.

The Problem It Solves

Before — getScreenCampaigns() in Kotlin launches a coroutine and returns immediately. The JS side received true immediately — before any network call had even started — and had no way to know when data was actually ready. The old hook guessed 1500ms:

TypeScript — OLD (polling hack, now removed)
await AppStorys.getScreenCampaigns(screenName);
// ❌ Hardcoded guess — wrong on slow networks, wasteful on fast ones
await new Promise(resolve => setTimeout(resolve, 1500));
const data = await AppStorys.getCampaigns();

The Solution — StateFlow → EventEmitter

The Kotlin bridge now collects core.campaigns (a StateFlow<List<Campaign>>) and emits "onCampaignsUpdate" events to JS every time the state changes. The JS hook subscribes to these events rather than polling.

Timing — Subscribe Before Fetch

The hook registers the subscription before calling getScreenCampaigns(). This is critical — if you reversed the order there would be a window where the native side emits before JS is listening and the update would be dropped.

TypeScript — correct order (from useCampaigns.ts)
// ✅ Subscribe FIRST
const subscription = emitter.addListener('onCampaignsUpdate', (json: string) => {
    setCampaigns(parseCampaignsJson(json));
    setLoading(false);
});

// ✅ THEN trigger the fetch
AppStorys.getScreenCampaigns(screenName);
🔄
Multiple components, one native listener. Because NativeEventEmitter is created at module level (outside the hook), all instances of useCampaigns across all mounted components share the same native EventEmitter. The core's coroutine collector runs once regardless of how many components subscribe — exactly like Flutter's asBroadcastStream() cache.

04 AppStorysModule.kt

The Kotlin bridge class. Every @ReactMethod here becomes callable from JS as AppStorysReactNative.methodName() and returns a Promise.

Kotlin — AppStorysModule.kt (full class structure)
class AppStorysModule(reactContext: ReactApplicationContext) :
    ReactContextBaseJavaModule(reactContext) {

    private val core: AppStorysCore             // shared KMP core
    private val moduleScope = CoroutineScope(SupervisorJob() + Dispatchers.IO)
    private var campaignsCollectorJob: Job? = null

    init {
        val storage = PlatformStorage()
        core = AppStorysCore(storage)
    }

    override fun getName() = "AppStorysReactNative"  // JS module name

    // ── EventEmitter pipeline ──────────────────────────────────────
    private fun emitCampaigns() {
        try {
            reactApplicationContext
                .getJSModule(DeviceEventManagerModule.RCTDeviceEventEmitter::class.java)
                .emit("onCampaignsUpdate", core.getCampaignsJson())
        } catch (_: Exception) { }   // bridge may be torn down during app background
    }

    private fun startCampaignsEmitter() {
        campaignsCollectorJob?.cancel()
        campaignsCollectorJob = moduleScope.launch {
            core.campaigns.collect { emitCampaigns() }
        }
    }

    // Required stubs — RN warns without these when NativeEventEmitter is used in JS
    @ReactMethod fun addListener(eventName: String) {}
    @ReactMethod fun removeListeners(count: Int) {}

    // ── Initialize ─────────────────────────────────────────────────
    @ReactMethod
    fun initialize(appId: String, accountId: String, userId: String, promise: Promise) {
        try {
            // Store device info for enrichment
            val storage = PlatformStorage()
            storage.putString("app_version", ...)
            storage.putString("package_name", ...)
            storage.putString("screen_width", ...)

            core.initialize(appId = appId, accountId = accountId, userId = userId)
            startCampaignsEmitter()   // ← start listening to StateFlow AFTER core is set up
            promise.resolve(true)
        } catch (e: Exception) { promise.reject("ERROR", e.message) }
    }
}

moduleScope vs core's scope

The core has its own CoroutineScope(SupervisorJob() + Dispatchers.Default) for all business logic. The module creates a separate moduleScope with Dispatchers.IO specifically for the campaigns collector coroutine. They are independent — if the collector crashes, it doesn't affect core operations and vice versa (SupervisorJob provides this isolation).

The addListener / removeListeners Stubs

React Native's NativeEventEmitter on the JS side calls addListener(eventName) and removeListeners(count) on the native module as bookkeeping methods. In newer RN versions (0.65+) the bridge emits a warning if these methods are missing. They don't need to do anything — the campaignsCollectorJob manages its own lifecycle.

invokeCoreMethodOrThrow — Reflection Bridge

Some methods (CSAT, Survey, Reels) use reflection to call core methods. This allows the module to call methods that were added to a newer core version without causing compile-time errors if the method doesn't exist in an older core.

Kotlin — reflection bridge (used for captureCsatResponse, captureSurveyResponse, sendReelLikeStatus)
private fun invokeCoreMethodOrThrow(methodName: String, vararg args: Any?) {
    val method = core.javaClass.methods.firstOrNull {
        it.name == methodName && it.parameterTypes.size == args.size
    } ?: throw NoSuchMethodException("$methodName not available in this AppStorysCore version")

    method.invoke(core, *args)
}

// Usage:
invokeCoreMethodOrThrow("captureCsatResponse", csatId, userId, rating, feedbackOption, additionalComments)

05 campaigns StateFlow → JS

The core.campaigns property is a StateFlow<List<Campaign>>. It lives in AppStorysCore and is the single source of truth for all campaign data. Every time _campaigns.emit() is called inside getScreenCampaigns(), the collect lambda in the module fires.

Kotlin — full emission chain from core to JS
// Inside AppStorysCore.getScreenCampaigns() — shared-core
_campaigns.emit(campaignsList)    // ← Step 1: core updates state

// Inside AppStorysModule.startCampaignsEmitter()
core.campaigns.collect {          // ← Step 2: collect fires
    emitCampaigns()
}

private fun emitCampaigns() {
    reactApplicationContext
        .getJSModule(DeviceEventManagerModule.RCTDeviceEventEmitter::class.java)
        .emit("onCampaignsUpdate", core.getCampaignsJson())   // ← Step 3: push JSON to JS
}

// getCampaignsJson() in AppStorysCore:
fun getCampaignsJson(): String {
    return SdkJson.encodeToString(          // ← Kotlin serialization → JSON string
        ListSerializer(CampaignDeserializer),
        _campaigns.value                     // reads current StateFlow value
    )
}

The JSON string arrives on the JS thread and is parsed by parseCampaignsJson() in the hook. The whole round trip — CDN fetch → StateFlow emit → Kotlin collector → RCT bridge → JS parse → React setState — completes in one pass, no polling.

When Does the StateFlow Emit?

TriggerEffect on StateFlow
getScreenCampaigns(screen) — screen changesEmits [] immediately (screen cleared), then emits data after CDN fetch
getScreenCampaigns(screen) — same screen, refreshEmits updated campaigns after CDN fetch
onAppStopped()Emits [] (cleared)
onAppResumed()Re-fetches; emits fresh data
disableCampaign(id)Does NOT emit — only updates _disabledCampaigns
⚠️
No StateFlow replay on new subscribers. Unlike Flutter's EventChannel (which has StateFlow replay semantics), the RN EventEmitter doesn't replay the last value to new subscribers. This is why the hook calls AppStorys.getScreenCampaigns(screenName) in useEffect — it explicitly triggers a new fetch (and therefore a new emit) when the component mounts.

06 index.ts — JS API Facade

The AppStorys object in src/index.ts is the only public surface that client developers interact with. It wraps the raw NativeModules.AppStorysReactNative calls with typed signatures and handles JSON parsing for array/map returns.

TypeScript — src/index.ts (complete facade)
const { AppStorysReactNative } = NativeModules;

export const AppStorys = {
    // ── Lifecycle ────────────────────────────────────────────────
    initialize: (appId: string, accountId: string, userId = ''): Promise<boolean> =>
        AppStorysReactNative.initialize(appId, accountId, userId),

    getScreenCampaigns: (screenName: string): Promise<boolean> =>
        AppStorysReactNative.getScreenCampaigns(screenName),

    isReady: (): Promise<boolean> =>
        AppStorysReactNative.isReady(),

    // ── Data Access ──────────────────────────────────────────────
    getCampaigns: async (): Promise<CampaignData[]> => {
        const json = await AppStorysReactNative.getCampaignsJson();
        if (!json || json === '[]') return [];
        return JSON.parse(json);
    },

    getCampaignsByType: async (type: string): Promise<CampaignData[]> => {
        const json = await AppStorysReactNative.getCampaignsByTypeJson(type);
        if (!json || json === '[]') return [];
        return JSON.parse(json);
    },

    getPersonalizationData: async (): Promise<Record<string, string>> => {
        const json = await AppStorysReactNative.getPersonalizationDataJson();
        if (!json || json === '{}') return {};
        return JSON.parse(json);
    },

    getUserId: (): Promise<string> =>
        AppStorysReactNative.getUserId(),

    // ── User ─────────────────────────────────────────────────────
    setUserId: (userId: string): Promise<boolean> =>
        AppStorysReactNative.setUserId(userId),

    setUserProperties: (attributes: Record<string, any>): Promise<boolean> =>
        AppStorysReactNative.setUserProperties(attributes),

    // ── Events ───────────────────────────────────────────────────
    trackEvent: (event: string, campaignId?: string | null, metadata?: Record<string, any>) =>
        AppStorysReactNative.trackEvent(campaignId ?? null, event, metadata ?? null),

    dismissCampaign: (campaignId: string): Promise<boolean> =>
        AppStorysReactNative.dismissCampaign(campaignId),

    // ── Response Capture ─────────────────────────────────────────
    captureCsatResponse: (csatId, rating, feedbackOption?, additionalComments?) =>
        AppStorysReactNative.captureCsatResponse(csatId, '', rating, feedbackOption ?? null, ...),

    captureSurveyResponse: (surveyId, responseOptions, comment?) =>
        AppStorysReactNative.captureSurveyResponse(surveyId, '', responseOptions, comment ?? null),

    sendReelLikeStatus: (campaignId, isLiked) =>
        AppStorysReactNative.sendReelLikeStatus(campaignId, '', isLiked),

    personalizeText: (text: string): Promise<string> =>
        AppStorysReactNative.personalizeText(text),

    // ── Navigation ───────────────────────────────────────────────
    handleNavigation: async (link: string): Promise<void> => {
        if (link.startsWith('http://') || link.startsWith('https://')) {
            await Linking.openURL(link);
        }
    },
};
📌
userId is passed as empty string to captureCsatResponse and captureSurveyResponse in the facade. This is because the Kotlin bridge uses core.userId internally — the JS doesn't need to pass it. The parameter exists in the native method signature for forward-compatibility.

07 CampaignData Model

The TypeScript type that represents a single campaign returned from the native JSON bridge. All fields are optional because different campaign types use different subsets.

TypeScript — CampaignData interface (src/index.ts)
export interface CampaignData {
    id?: string;               // campaign UUID
    campaign_id?: string;      // alias for id (may differ depending on campaign type)
    campaign_type?: string;    // "BAN" | "FLT" | "MOD" | "CSAT" | "SUR" | "STR" | ...
    screen?: string;           // screen name the campaign is registered to
    position?: string;         // for WID type — widget position identifier
    trigger_event?: string;    // event name or JSON condition that shows the campaign
    details?: Record<string, any>;   // type-specific data (image, link, styling, etc.)
    image?: string;            // convenience — may also be inside details.image
    link?: string;             // CTA destination URL or deep link
    width?: number;            // campaign media width in dp/points
    height?: number;           // campaign media height in dp/points
    styling?: Record<string, any>; // border radii, margins, cross button config
    lottie_data?: string;      // Lottie animation URL (if applicable)
}

Why Two ID Fields?

Shared-core serializes the campaign id field. Some campaign types nest the ID differently. The normalizeCampaign() utility in campaignParser.ts ensures that campaign_id is always set to id if not already present, so components can safely read either one.

Reading Campaign Details

Campaign-specific data lives in details. The same data is also flattened to top-level fields (image, link, width, height, styling) by the core before emitting. Components always check both:

TypeScript — reading campaign data safely
const campaign = campaigns.find(c => c.campaign_type === 'BAN');
const details = (campaign?.details as Record<string, any>) ?? campaign ?? {};

// Always check details first, fall back to top-level
const imageUrl = details.image ?? campaign?.image;
const link     = details.link  ?? campaign?.link;
const styling  = details.styling ?? campaign?.styling ?? {};

08 campaignParser Utilities

Three pure utility functions in src/utils/campaignParser.ts used throughout the SDK and available for client code.

TypeScript — src/utils/campaignParser.ts
// 1. Parse a raw JSON string into a CampaignData array.
// Returns [] on empty, null, or parse error — never throws.
export function parseCampaignsJson(json: string | null | undefined): CampaignData[] {
    if (!json || json === '[]') return [];
    try {
        const raw = JSON.parse(json);
        if (!Array.isArray(raw)) return [];
        return raw.map(item => normalizeCampaign(item ?? {}));
    } catch { return []; }
}

// 2. Normalize a raw campaign object — flattens details to top-level,
// ensures campaign_id is always set, coerces width/height to numbers.
export function normalizeCampaign(input: Partial<CampaignData> & Record<string, any>): CampaignData {
    const details = (input.details ?? {}) as Record<string, any>;
    return {
        id: input.id,
        campaign_id: input.campaign_id ?? input.id,
        campaign_type: input.campaign_type,
        screen: input.screen,
        position: input.position,
        trigger_event: input.trigger_event,
        details,
        image: input.image ?? details.image,
        link: input.link ?? details.link,
        width: toNumber(input.width ?? details.width),
        height: toNumber(input.height ?? details.height),
        styling: input.styling ?? details.styling,
        lottie_data: input.lottie_data ?? details.lottie_data,
    };
}

// 3. Filter an array of campaigns by campaign_type code.
export function filterCampaignsByType(campaigns: CampaignData[], type: string): CampaignData[] {
    return campaigns.filter(c => c.campaign_type === type);
}

09 useCampaigns (EventEmitter)

The primary hook. Every screen that needs campaigns uses this. It manages the EventEmitter subscription lifecycle and exposes campaigns, loading, refresh, and getCampaignsByType.

TypeScript — src/hooks/useCampaigns.ts (complete)
import { useState, useEffect, useCallback } from 'react';
import { NativeEventEmitter, NativeModules } from 'react-native';
import AppStorys, { CampaignData } from '../index';
import { parseCampaignsJson, filterCampaignsByType } from '../utils/campaignParser';

const { AppStorysReactNative } = NativeModules;

// Module-level singleton — all hook instances share one native listener.
// Equivalent to Flutter's asBroadcastStream() cache.
const emitter = new NativeEventEmitter(AppStorysReactNative);

export function useCampaigns(screenName: string) {
    const [campaigns, setCampaigns] = useState<CampaignData[]>([]);
    const [loading, setLoading] = useState(true);

    useEffect(() => {
        setLoading(true);
        setCampaigns([]);  // clear stale data from previous screen

        // ✅ Subscribe BEFORE triggering fetch — no emission is missed.
        // Equivalent to Flutter's CampaignsStreamMixin.subscribeToCampaigns()
        const subscription = emitter.addListener('onCampaignsUpdate', (json: string) => {
            setCampaigns(parseCampaignsJson(json));
            setLoading(false);
        });

        // Trigger the native fetch. Data arrives via the subscription above.
        AppStorys.getScreenCampaigns(screenName).catch(() => setLoading(false));

        // Cleanup when component unmounts or screenName changes.
        // Equivalent to Flutter's CampaignsStreamMixin.dispose()
        return () => subscription.remove();
    }, [screenName]);

    const getCampaignsByType = useCallback(
        (type: string) => filterCampaignsByType(campaigns, type),
        [campaigns]
    );

    // Force a re-fetch (e.g. pull-to-refresh)
    const refresh = useCallback(() => {
        setLoading(true);
        AppStorys.getScreenCampaigns(screenName).catch(() => setLoading(false));
    }, [screenName]);

    return { campaigns, loading, refresh, getCampaignsByType };
}

Lifecycle of the Hook

EventWhat Happens
Component mountsuseEffect runs: subscribes to emitter, calls getScreenCampaigns
Native CDN fetch completesStateFlow emits → Kotlin collector → emitCampaigns() → onCampaignsUpdate event → setCampaigns()
screenName prop changesuseEffect re-runs: old subscription removed, new one created, new fetch triggered
Component unmountssubscription.remove() — no more events delivered to this component
refresh() calledsetLoading(true), new getScreenCampaigns call → new emission

getCampaignsByType

A convenience method on the hook return value. It filters the current campaigns array in memory — no extra network call. The result is memoized with useCallback so it doesn't re-create on every render.

TypeScript — using getCampaignsByType
const { campaigns, loading, getCampaignsByType } = useCampaigns('HomeScreen');

const banners   = getCampaignsByType('BAN');
const floaters  = getCampaignsByType('FLT');
const modals    = getCampaignsByType('MOD');
// All read from the same campaigns array — no re-fetching

10 useAppStorys

A lifecycle hook for initialization. Handles the async initialize flow and exposes ready, initializing, and error state. Typically used once in your root component.

TypeScript — src/hooks/useAppStorys.ts
export function useAppStorys(options: UseAppStorysOptions) {
    const { appId, accountId, userId = '', autoInitialize = true } = options;
    const [initializing, setInitializing] = useState(false);
    const [ready, setReady] = useState(false);
    const [error, setError] = useState<Error | null>(null);

    const initialize = useCallback(async () => {
        setInitializing(true);
        try {
            await AppStorys.initialize(appId, accountId, userId);
            const sdkReady = await AppStorys.isReady();   // poll core sdkState
            setReady(sdkReady);
        } catch (e) {
            setError(e instanceof Error ? e : new Error('Failed to initialize'));
            setReady(false);
        } finally { setInitializing(false); }
    }, [appId, accountId, userId]);

    useEffect(() => {
        if (autoInitialize) initialize();
    }, [autoInitialize, initialize]);

    return { initialize, initializing, ready, error };
}
💡
initialize() resolves immediately — the underlying Kotlin core.initialize() launches its coroutine and returns. The isReady() call that follows reads core.sdkState, but the token fetch may not have completed yet. For production apps, use useCampaigns which doesn't depend on ready — the EventEmitter handles the timing.

Usage

TypeScript — typical root component usage
export default function App() {
    const { ready, initializing, error } = useAppStorys({
        appId: 'your-app-id',
        accountId: 'your-account-id',
        userId: 'user-123',
    });

    if (initializing) return <LoadingScreen />;
    if (error) return <ErrorScreen message={error.message} />;
    return <MainNavigator />;
}

11 Banner Component

Displays a BAN-type campaign as a full-width image with optional close button. Tracks viewed on mount and clicked on tap. Width, height, and border radii are read from campaign styling for pixel-perfect presentation.

TypeScript — Banner.tsx key logic
export function Banner({ campaigns, onDismiss }: BannerProps) {
    const [visible, setVisible] = useState(true);

    const banner = useMemo(
        () => campaigns.find(c => c.campaign_type === 'BAN'),
        [campaigns]
    );
    const details  = (banner?.details ?? banner ?? {}) as Record<string, any>;
    const styling  = (details.styling ?? banner?.styling ?? {}) as Record<string, any>;
    const imageUrl = details.image ?? banner?.image;

    // Track viewed on mount
    useEffect(() => {
        if (campaignId) AppStorys.trackEvent('viewed', campaignId);
    }, [campaignId]);

    if (!banner || !visible || !imageUrl) return null;

    // Responsive height from campaign dimensions
    const availableWidth = screenWidth - ml - mr;
    const imageHeight = w > 0 && h > 0 ? availableWidth * (h / w) : h || undefined;

    const handlePress = async () => {
        await AppStorys.trackEvent('clicked', campaignId);
        await AppStorys.handleNavigation(link);
    };

    const handleDismiss = async () => {
        await AppStorys.dismissCampaign(campaignId);
        setVisible(false);
        onDismiss?.(campaignId);
    };

    return (
        <View style={{ marginBottom: mb, marginLeft: ml, marginRight: mr }}>
            <TouchableOpacity onPress={handlePress}>
                <Image source={{ uri: imageUrl }} style={{ height: imageHeight, borderRadius: ... }} />
            </TouchableOpacity>
            {showClose && <CloseButton onPress={handleDismiss} />}
        </View>
    );
}

12 Floater Component

Displays a FLT-type campaign as a fixed circular overlay anchored to the bottom-right corner. Unlike the Flutter version which uses an Align widget inside a Stack, the RN Floater uses position: 'absolute' in StyleSheet.

TypeScript — Floater.tsx
export function Floater({ campaigns }: FloaterProps) {
    const campaign = campaigns.find(c => c.campaign_type === 'FLT');
    if (!campaign) return null;

    const image = details.image ?? campaign.image;
    if (!image) return null;

    const onPress = async () => {
        if (campaignId) await AppStorys.trackEvent('clicked', campaignId);
        if (link) await AppStorys.handleNavigation(link);
    };

    return (
        <View style={styles.container} pointerEvents="box-none">
            <TouchableOpacity onPress={onPress}>
                <Image source={{ uri: image }} style={styles.image} />
            </TouchableOpacity>
        </View>
    );
}

const styles = StyleSheet.create({
    container: { position: 'absolute', right: 16, bottom: 16 },
    image: { width: 64, height: 64, borderRadius: 32 },
});
⚠️
Placement matters. Floater uses position: 'absolute' so it must be placed inside a View with flex: 1 and position: 'relative'. The parent View also needs pointerEvents="box-none" to let touches pass through to underlying content.

18 Event Tracking

Events flow from JS → Kotlin bridge → core.trackEvent() → API. Non-system events are also added to the core's _trackedEvents StateFlow, which the TriggerEventMatcher uses to evaluate whether trigger-based campaigns should show.

trackEvent

AppStorys.trackEvent(event, campaignId?, metadata?): Promise<boolean>
TypeScript — trackEvent examples
// System events — sent to API only, NOT added to TriggerEventMatcher
await AppStorys.trackEvent('viewed', campaignId);
await AppStorys.trackEvent('clicked', campaignId);

// Custom events — sent to API AND added to _trackedEvents for trigger matching
await AppStorys.trackEvent('checkout_complete');
await AppStorys.trackEvent('item_added', null, { itemId: 'SKU123', price: 49.99 });

// With campaign ID (attaches variant ID to API payload automatically)
await AppStorys.trackEvent('form_submitted', campaignId, { step: 3 });

System Events

These event names are treated specially by the core — they go to the API but do NOT affect trigger matching. All other event names are considered custom and update _trackedEvents:

viewed clicked csat captured survey captured shared SurveySubmitted SurveyDismissed ThankYouCTAClicked

dismissCampaign

AppStorys.dismissCampaign(campaignId): Promise<boolean>

Adds campaignId to _disabledCampaigns in the core. The campaign will no longer be returned by getFilteredCampaigns() for the rest of the session. Called automatically by Modal and BottomSheet components when closed.

19 User Management

Anonymous Users

When initialize() is called without a userId, the core generates an anonymous ID (<random13digits>_anonymous) and stores it in PlatformStorage. Subsequent app launches reuse the same anonymous ID.

setUserId — Anonymous Reconciliation

AppStorys.setUserId(userId): Promise<boolean>

When called after an anonymous session, the core calls the reconcileAnonymousUser API endpoint which merges the anonymous user's campaign history into the new identified user. This is a one-way migration — once reconciled, the session is no longer anonymous.

TypeScript — setUserId after login
async function onLoginSuccess(userId: string) {
    // Reconciles anonymous history → identified user in one API call
    await AppStorys.setUserId(userId);
    // Now re-fetch campaigns — the user may be eligible for different ones
    await AppStorys.getScreenCampaigns(currentScreen);
}

20 Personalization

Personalization replaces {{token}} placeholders in campaign text with values from the backend. The RN SDK has both a server-side approach (calling through the Kotlin bridge) and a client-side approach (pure TypeScript).

Server-Side: personalizeText

AppStorys.personalizeText(text): Promise<string>

Calls through to core.personalizeText() which uses the personalization map fetched alongside campaigns. Guarantees server-synchronized data.

TypeScript
const greeting = await AppStorys.personalizeText('Hello {{user.name}}, you have {{rewards.points}} points');
// → "Hello Yash, you have 240 points"

Client-Side: personalization utilities

The src/utils/personalization.ts module provides pure JS utilities for offline/local personalization:

TypeScript — personalization utils
import { personalizeText, personalizeObject, parsePersonalizationJson } from 'appstorys-react-native';

// 1. Replace tokens in a string
const result = personalizeText('Hello {{name}}!', { name: 'Yash' });

// 2. Replace tokens recursively in any object/array
const personalized = personalizeObject(campaignDetails, personalizationMap);

// 3. Parse the JSON from getPersonalizationData()
const data = parsePersonalizationJson(await AppStorys.getPersonalizationData());
const text = personalizeText('Your plan is {{plan}}', data);
