Section 01

Architecture — How It All Fits Together

The entire SDK is built around a single source of truth: AppStorysCore. Every platform (Android, Flutter, React Native) uses the same core via KMP — no duplicated logic, no diverging behavior.

Android
App
Kotlin Test App — Jetpack Compose UI
App.kt initializes. MainActivity hosts NavHost + overlayElements. HomeScreen / PayScreen / TestScreen call getScreenCampaigns + render campaign composables.
Android
SDK
AppStorys Android Wrapper — Composable Campaign Widgets
Wraps AppStorysCore. Exposes Compose UI: Stories(), Widget(), Milestone(), overlayElements(). Observes StateFlows directly.
CORE
AppStorysCore — KMP Engine (shared-core)
All business logic. StateFlows, HTTP calls, variant extraction, trigger matching, user state, JSON bridge methods. Shared by Android, Flutter, and React Native.
API
Layer
ApiClient — Ktor HTTP
All network calls. Validate-account, track-user-res, CDN campaigns.json (with ETag caching), capture-event, CSAT, Survey, Reels, reconcile. Pure Kotlin, no Android imports.
Platform
Storage
PlatformStorage — expect/actual KMP
Android: SharedPreferences. iOS: NSUserDefaults. Same interface everywhere. Stores access token, userId, anonymousFlag, ETag, campaigns cache.
Section 02

What is KMP (Kotlin Multiplatform)?

KMP lets you write business logic once in Kotlin and compile it to multiple targets — Android (JVM), iOS (Native), JavaScript. Each target gets a native binary — no interpreter, no runtime penalty.

Common code

Everything in commonMain — AppStorysCore, ApiClient, all models, TriggerEventMatcher. Compiles to ALL targets. Zero platform imports allowed here.

Platform-specific code

The expect/actual pattern. expect class PlatformStorage is declared in commonMain. actual class PlatformStorage is implemented separately in androidMain (SharedPreferences) and iosMain (NSUserDefaults).

Section 03

Internal State & StateFlows

AppStorysCore holds all SDK state. Nothing is stored in Activities, ViewModels, or singletons. Every consumer (Android, Flutter, RN) reads from these same fields.

AppStorysCore.kt — all state fields
class AppStorysCore(private val storage: PlatformStorage) {

    // Coroutine scope — SupervisorJob: one failed child doesn't kill others
    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.Default)

    // ── Authentication ─────────────────────────────────────────────
    var accessToken: String = ""       private set   // JWT from validate-account
    var userId: String = ""            private set   // current user (real or anon)
    var isAnonymousUser: Boolean = true private set  // false after setUserId()
    var isTestUser: Boolean = false    private set   // true if dashboard marks as test
    var appId: String = ""
    var accountId: String = ""

    // ── SDK Lifecycle ──────────────────────────────────────────────
    enum class SdkState { Uninitialized, Initializing, Initialized, Paused, Error }
    var sdkState: SdkState = SdkState.Uninitialized  private set

    // ── The 4 StateFlows ──────────────────────────────────────────
    // All are MutableStateFlow internally, exposed as read-only StateFlow.
    // StateFlow REPLAYS the current value to every new collector.

    private val _campaigns = MutableStateFlow<List<Campaign>>(emptyList())
    val campaigns: StateFlow<List<Campaign>> = _campaigns.asStateFlow()
    // Emits whenever getScreenCampaigns() completes — all widgets react

    private val _disabledCampaigns = MutableStateFlow<List<String>>(emptyList())
    val disabledCampaigns: StateFlow<List<String>> = _disabledCampaigns.asStateFlow()
    // Grows when dismissCampaign() is called — resets on screen change

    private val _trackedEvents = MutableStateFlow<Set<TrackedEventData>>(emptySet())
    val trackedEvents: StateFlow<Set<TrackedEventData>> = _trackedEvents.asStateFlow()
    // Grows when trackEvent() / viaAppStorys() is called — gates trigger campaigns

    private val _campaignVariants = MutableStateFlow<List<CampaignVariant>>(emptyList())
    val campaignVariants: StateFlow<List<CampaignVariant>> = _campaignVariants.asStateFlow()
    // Stores which variant each user is assigned — used for trackEvent variant_id

    // ── Other state ────────────────────────────────────────────────
    var currentScreen: String = ""     private set   // last screen name passed to getScreenCampaigns
    private var personalizationData: Map<String, String>? = null   // from track-user-res
    private var campaignsJob: Job? = null   // active fetch job — cancelled on screen change
    private val deviceInfo: Map<String, Any> = getDeviceInfo()
}
🔑
StateFlow Replay — the key guarantee

Unlike a regular Flow, StateFlow always holds the latest value. Any new collector gets it immediately on subscription. This is why Android composables and Flutter widgets don't miss campaigns even if they mount after getScreenCampaigns() completed.

Section 04

The Initialize Flow

Initialization is a 3-step async process. The Kotlin coroutine runs on Dispatchers.Default — the calling thread is never blocked.

AppStorysCore.kt — initialize()
fun initialize(appId: String, accountId: String, userId: String = "") {
    this.appId = appId
    this.accountId = accountId

    // ── Step 1: Resolve user identity ───────────────────────────────────────
    if (userId.isNotEmpty()) {
        // Real user provided — store it, mark as non-anonymous
        this.userId = userId
        this.isAnonymousUser = false
        storage.putString("appstorys_user_id", userId)
        storage.putBoolean("appstorys_is_anonymous", false)
    } else {
        val saved = storage.getString("appstorys_user_id")
        if (!saved.isNullOrEmpty()) {
            // Previous session exists — restore it
            this.userId = saved
            this.isAnonymousUser = storage.getBoolean("appstorys_is_anonymous", true)
        } else {
            // First launch — generate anonymous ID, persist it
            this.userId = "${randomAnonymousSuffix()}_anonymous"
            this.isAnonymousUser = true
            storage.putString("appstorys_user_id", this.userId)
            storage.putBoolean("appstorys_is_anonymous", true)
        }
    }

    // ── Guard: skip if already initialized ──────────────────────────────────
    if (sdkState == SdkState.Initialized || sdkState == SdkState.Initializing) return
    sdkState = SdkState.Initializing

    // ── Steps 2 + 3 run in a coroutine ──────────────────────────────────────
    scope.launch {
        try {
            // Step 2: POST validate-account → get Bearer access token
            val tokenResult = apiClient.validateAccount(
                accountId = accountId,
                request = ValidateAccountRequest(
                    app_id = appId,
                    account_id = accountId,
                    user_id = this@AppStorysCore.userId,
                    attributes = null
                )
            )

            if (tokenResult is ApiResult.Success && !tokenResult.data.access_token.isNullOrBlank()) {
                accessToken = tokenResult.data.access_token!!
                sdkState = SdkState.Initialized

                // Step 3: Fetch campaigns for whatever screen was already set
                // campaignsJob.isActive guard prevents duplicate fetch if
                // getScreenCampaigns() was called before init completed
                if (campaignsJob?.isActive != true) {
                    getScreenCampaigns(currentScreen, emptyList())
                }
            } else {
                sdkState = SdkState.Error
            }
        } catch (e: Exception) {
            sdkState = SdkState.Error
        }
    }
}

User Identity Resolution

The core always has a userId — never null. The resolution priority is:

1
Real userId provided
userId = provided value, isAnonymousUser = false. Stored in PlatformStorage.
2
No userId but previous session exists in storage
userId = stored value. isAnonymousUser = stored flag. Session continuity preserved.
3
First launch, no userId
Generates: "{13-digit-random}_anonymous". Persists to storage. isAnonymousUser = true.
Section 05

getScreenCampaigns — The Campaign Fetch Pipeline

This is the most complex method in the core. It performs up to 3 HTTP calls and resolves variants before updating the StateFlow.

AppStorysCore.kt — getScreenCampaigns()
fun getScreenCampaigns(screenName: String, positionList: List<String> = emptyList()) {
    campaignsJob?.cancel()   // ← cancel previous screen's in-flight fetch
    campaignsJob = scope.launch {

        // waitForInit() polls every 100ms until sdkState == Initialized (max 5s)
        // Needed because getScreenCampaigns() might be called before init completes
        if (!waitForInit()) return@launch

        ensureActive()  // bail if this job was already cancelled

        // ── Screen change: reset all per-screen state ─────────────────────
        if (currentScreen != screenName) {
            _disabledCampaigns.emit(emptyList())  // dismissed campaigns reset
            _campaigns.emit(emptyList())           // clear UI immediately
            _trackedEvents.emit(emptySet())        // trigger events reset
            currentScreen = screenName
            delay(100)    // small debounce — prevents flicker on fast tab switches
        }

        ensureActive()

        // ── HTTP 1: POST track-user-res ───────────────────────────────────
        // Asks the server: "which campaign IDs is this user eligible for?"
        // Also returns: variants assignment, personalization data, test_user flag
        val eligibleResult = apiClient.getEligibleCampaigns(
            accountId = accountId,
            accessToken = accessToken,
            request = TrackUserWebSocketRequest(
                user_id = userId,
                screenName = currentScreen
            )
        )
        val eligibleCampaignIds = eligibleResult.data.eligibleCampaignList ?: emptyList()

        // ── HTTP 2: GET campaigns.json from S3 CDN ────────────────────────
        // Full campaign definitions. Uses ETag — 304 means serve from cache.
        val allCampaigns = apiClient.fetchCampaignsJson(accountId = accountId).data

        // ── HTTP 3 (optional): load missing campaigns ─────────────────────
        // If any eligible IDs are not in the CDN cache, fetch them individually
        val cachedIds = allCampaigns.mapNotNull { it.id }.toSet()
        val missingIds = eligibleCampaignIds.filter { it !in cachedIds }
        if (missingIds.isNotEmpty()) {
            val missingResult = apiClient.loadMissingCampaigns(
                accessToken = accessToken,
                campaignIds = missingIds
            )
            // merge into allCampaigns
        }

        // ── Filter: screen + eligibility ──────────────────────────────────
        val variants = eligibleResult.data.variants ?: emptyList()

        val campaignsList = allCampaigns
            .filter { campaign ->
                campaign.id in eligibleCampaignIds &&
                campaign.screen?.equals(currentScreen, ignoreCase = true) == true
            }
            .map { campaign ->
                // Resolve variant BEFORE emitting — all platforms get resolved data
                val variant = variants.find { it.id == campaign.id }
                if (variant != null) extractVariantFromCampaign(campaign, variant.v_id)
                else campaign
            }

        // ── Emit → all observers update ───────────────────────────────────
        _campaigns.emit(campaignsList)
        _campaignVariants.emit(variants)

        // ── Test-user only: identify widget positions ─────────────────────
        if (isTestUser && positionList.isNotEmpty()) {
            apiClient.identifyPositions(accessToken, positionList, currentScreen)
        }
    }
}

The waitForInit() Pattern

// Polls until initialized or times out after 5 seconds (50 × 100ms)
private suspend fun waitForInit(): Boolean {
    var attempts = 0
    while (sdkState == SdkState.Initializing && attempts < 50) {
        delay(100)
        attempts++
    }
    return sdkState == SdkState.Initialized
}
⚠️
The CDN ETag Cache

The CDN returns 304 Not Modified when campaigns haven't changed. The core stores both the ETag and the full JSON in PlatformStorage. On 304, it deserializes the cached JSON instead of downloading again. On network failure, it falls back to cached JSON rather than failing hard.

Section 06

Variant Extraction — A/B Testing

Campaigns can have multiple variants (A/B/C testing). The track-user-res response tells the core which variant each user is assigned. The core resolves variants before emitting — so all platforms always receive already-resolved campaigns.

AppStorysCore.kt — extractVariantFromCampaign()
private fun extractVariantFromCampaign(campaign: Campaign, variantId: String): Campaign {
    val details = campaign.details
    if (details !is VariantCampaignDetails) return campaign  // not a variant campaign

    // Get the specific variant's JSON object
    val variantData = details.variants[variantId]?.jsonObject ?: return campaign

    // Deserialize into the correct typed details object based on campaign type
    val variantDetails = when (campaign.campaignType) {
        "BAN"  -> SdkJson.decodeFromJsonElement<BannerDetails>(variantData)
        "FLT"  -> SdkJson.decodeFromJsonElement<FloaterDetails>(variantData)
        "CSAT" -> SdkJson.decodeFromJsonElement<CSATDetails>(variantData)
        "WID"  -> SdkJson.decodeFromJsonElement<WidgetDetails>(variantData)
        "REL"  -> SdkJson.decodeFromJsonElement<ReelsDetails>(variantData)
        "TTP"  -> SdkJson.decodeFromJsonElement<TooltipsDetails>(variantData)
        "PIP"  -> SdkJson.decodeFromJsonElement<PipDetails>(variantData)
        "BTS"  -> SdkJson.decodeFromJsonElement<BottomSheetDetails>(variantData)
        "SUR"  -> SdkJson.decodeFromJsonElement<SurveyDetails>(variantData)
        "MOD"  -> SdkJson.decodeFromJsonElement<ModalDetails>(variantData)
        "STR"  -> StoriesDetails(SdkJson.decodeFromJsonElement<List<StoryGroup>>(variantData))
        "SCRT" -> SdkJson.decodeFromJsonElement<ScratchCardDetails>(variantData)
        "MIL"  -> SdkJson.decodeFromJsonElement<MilestoneDetails>(variantData)
        "STW"  -> SdkJson.decodeFromJsonElement<SpinTheWheelDetails>(variantData)
        else -> null
    }

    // Return new Campaign with variant details replacing VariantCampaignDetails
    return if (variantDetails != null) campaign.copy(details = variantDetails) else campaign
}
🧬
Why resolve before emitting?

Flutter and React Native receive campaigns as raw JSON. If variants were left as VariantCampaignDetails, every platform would need to implement its own variant resolution logic. Resolving in core means all platforms get a clean, typed object — consistent behavior, zero duplication.

Section 07

TriggerEventMatcher — Conditional Campaigns

Not all campaigns show on screen load. Some are gated behind user actions — a login, a purchase, a back press. TriggerEventMatcher evaluates whether a campaign's conditions are met.

How Trigger Campaigns Work

Every campaign has an optional trigger_event field from the dashboard. When a user fires an event via trackEvent(), it's added to _trackedEvents. getFilteredCampaigns() checks this set before returning any campaign.

TriggerEventMatcher.kt — shouldShowCampaign()
fun shouldShowCampaign(
    triggerEvent: TriggerEvent?,
    campaignId: String?,
    trackedEvents: Set<TrackedEventData>
): Boolean {
    if (triggerEvent == null) return true   // no trigger = always show

    return when (triggerEvent) {

        // Simple string trigger — campaign shows if this event name was tracked
        is TriggerEvent.StringTrigger -> {
            if (triggerEvent.event.isEmpty()) return true
            val eventToMatch = if (triggerEvent.event == "viaAppStorys") {
                // viaAppStorys trigger uses campaign-specific sentinel
                "viaAppStorys${campaignId}"
            } else {
                triggerEvent.event
            }
            trackedEvents.any { it.eventName == eventToMatch }
        }

        // Object trigger — event name + condition matching on metadata
        is TriggerEvent.ObjectTrigger -> {
            if (triggerEvent.event.isEmpty()) return true

            // Back-press campaigns only evaluate after back is actually pressed
            val isBackPressCampaign = triggerEvent.eventConfig.any { it.backPress == true }
            if (isBackPressCampaign) {
                val backPressTriggered = trackedEvents.any {
                    it.eventName == BACK_PRESS_SENTINEL  // "__back_press_triggered__"
                }
                if (!backPressTriggered) return false
            }

            // Check if any tracked event with the right name satisfies all conditions
            val matchingEvents = trackedEvents.filter { it.eventName == triggerEvent.event }
            matchingEvents.any { tracked ->
                matchesAllConditions(triggerEvent.eventConfig, tracked.metadata)
            }
        }
    }
}

Condition Operators

// Supported operators on metadata values — configured on the dashboard
"eq"  → metadataValue == conditionValue
"neq" → metadataValue != conditionValue
"gt"  → metadataValue.toDouble() > conditionValue.toDouble()
"gte" → metadataValue.toDouble() >= conditionValue.toDouble()
"lt"  → metadataValue.toDouble() < conditionValue.toDouble()
"lte" → metadataValue.toDouble() <= conditionValue.toDouble()

Practical Example

// Dashboard config: show Modal after Login event where age > 25

// In app code:

    event = "Login",
    metadata = mapOf("age" to 34, "name" to "Yash")
)

// Core adds TrackedEventData("Login", {"age": 34, "name": "Yash"}) to _trackedEvents

// TriggerEventMatcher evaluates:
//   triggerEvent.event == "Login" ✓
//   condition: key="age", operator="gt", value="25"
//   metadata["age"].toDouble() = 34 > 25 ✓
// → shouldShowCampaign returns true → Modal is included in getFilteredCampaigns()

Back-Press Campaigns

core.injectBackPressSentinel()
// → adds TrackedEventData("__back_press_triggered__") to _trackedEvents
// → back_press campaigns now evaluate their real conditions
// → if conditions pass → campaign shows (e.g. exit intent Modal)

// After consuming:

// → removes the event from _trackedEvents so it doesn't re-trigger

ApiClient — All Network Calls

Built on Ktor — a KMP HTTP client that compiles to Android (OkHttp engine) and iOS (Darwin engine). All calls return ApiResult<T> — a sealed class with Success and Error variants.

ApiResult — every call returns this
sealed class ApiResult<out T> {
    data class Success<T>(val data: T) : ApiResult<T>()
    data class Error(val message: String, val code: Int? = null) : ApiResult<Nothing>()
}

Ktor Client Configuration

private fun createDefaultHttpClient(): HttpClient {
    return HttpClient {
        install(ContentNegotiation) {
            json(apiJson)  // kotlinx-serialization JSON
        }
        install(HttpTimeout) {
            requestTimeoutMillis = 30_000   // 30s all timeouts
            connectTimeoutMillis = 30_000
            socketTimeoutMillis = 30_000
        }
        install(Logging) {
            level = LogLevel.INFO  // logs REQUEST + RESPONSE to Logcat/console
        }
    }
}

// JSON parser — lenient, ignores unknown keys (future API fields won't crash)
val apiJson = Json {
    ignoreUnknownKeys = true
    isLenient = true
    coerceInputValues = true
    explicitNulls = false
}

CDN Caching with ETag

suspend fun fetchCampaignsJson(accountId: String): ApiResult<List<Campaign>> {
    val cachedEtag = storage.getString("campaigns_etag_$accountId")

    val response = httpClient.get("$CDN_BASE_URL/clients/$accountId/campaigns.json") {
        cachedEtag?.let { header(HttpHeaders.IfNoneMatch, it) }  // ← conditional GET
    }

    return when (response.status.value) {
        200 -> {
            // Fresh data — cache it and update ETag
            val payload = response.body<String>()
            storage.putString("campaigns_json_$accountId", payload)
            storage.putString("campaigns_etag_$accountId", response.headers[HttpHeaders.ETag])
            ApiResult.Success(decodeCampaigns(payload))
        }
        304 -> {
            // Nothing changed — serve from cache
            val cached = storage.getString("campaigns_json_$accountId")
            ApiResult.Success(decodeCampaigns(cached!!))
        }
        else -> fallbackToCachedCampaigns(...)   // network error → serve stale cache
    }
}
🚀
304 Not Modified

After the first app launch, campaigns.json is cached. Subsequent getScreenCampaigns() calls get a 304 response — the full JSON is never re-downloaded. This makes campaign loads near-instant after first run.

safeCall — Uniform Error Handling

// All simple request/response calls use this — eliminates duplicated try/catch
private suspend inline fun <reified T> safeCall(
    operation: String,
    call: () -> HttpResponse
): ApiResult<T> {
    return try {
        val response = call()
        if (!response.status.isSuccess()) {
            ApiResult.Error("Request failed with code ${response.status.value}", response.status.value)
        } else {
            ApiResult.Success(response.body())   // auto-deserializes via ContentNegotiation
        }
    } catch (e: Exception) {
        ApiResult.Error(message = e.message ?: "Unexpected error")
    }
}

Section 10

Lifecycle Management

The core tracks app foreground/background state so campaigns don't render in the background and are refreshed when the app returns.

AppStorysCore.kt — lifecycle methods
fun onAppResumed() {
    // Called from Activity.onResume() via the Android wrapper
    if (sdkState == SdkState.Paused && currentScreen.isNotBlank()) {
        sdkState = SdkState.Initialized
        // Re-fetch for the screen we were on — user may have been away a while
        getScreenCampaigns(currentScreen, emptyList())
    }
}

fun onAppStopped() {
    // Called from Activity.onStop() via the Android wrapper
    sdkState = SdkState.Paused
    scope.launch {
        _campaigns.emit(emptyList())      // clear campaigns — don't render in bg
        _trackedEvents.emit(emptySet())   // clear tracked events
    }
    campaignsJob?.cancel()   // stop any in-flight fetch
    campaignsJob = null
}

fun destroy() {
    scope.cancel()   // cancel ALL coroutines — called on app process death
}

User Management

setUserId — Anonymous to Identified

fun setUserId(newUserId: String) {
    scope.launch {
        val previousUserId = userId
        val wasAnonymous = isAnonymousUser

        // Already this userId — no-op
        if (!wasAnonymous && previousUserId == newUserId) return@launch

        try {
            if (wasAnonymous) {
                // Merge anonymous session into identified account
                // Backend links campaign views/clicks from anonymous period
                apiClient.reconcileAnonymousUser(
                    accessToken = accessToken,
                    request = ReconcileUserRequest(
                        anonymous_user_id = previousUserId,   // "9123456789012_anonymous"
                        identified_user_id = newUserId        // "yash@example.com"
                    )
                )
            }

            userId = newUserId
            isAnonymousUser = false
            storage.putString("appstorys_user_id", newUserId)
            storage.putBoolean("appstorys_is_anonymous", false)
        } catch (e: Exception) { ... }
    }
}

trackEvent

fun trackEvent(campaignId: String? = null, event: String, metadata: Map<String, Any>? = null) {
    scope.launch {
        // System events (viewed, clicked, etc.) are NOT added to _trackedEvents
        // — they're analytics only, not trigger gates
        val systemEvents = setOf("viewed", "clicked", "csat captured", "survey captured", ...)

        if (event !in systemEvents) {
            // Custom events ARE added — they can gate trigger campaigns
            _trackedEvents.update { it + TrackedEventData(event, metadata) }
        }

        // Look up variant_id for this campaign (if any) to send with the event
        val variantId = campaignId?.let { id ->
            _campaignVariants.value.find { it.id == id }?.v_id
        }

        // Merge metadata + device info + variant_id into final payload
        val finalMetadata = (metadata ?: emptyMap()) + deviceInfo +
            (if (variantId != null) mapOf("variant_id" to variantId) else emptyMap())

        apiClient.captureEvent(
            accessToken = accessToken,
            userId = userId,
            campaignId = campaignId,
            event = event,
            metadata = finalMetadata
        )
    }
}

// getFilteredCampaigns — used by Android composables directly (no JSON serialization needed)
fun getFilteredCampaigns(campaignType: String, disabledIds: List<String> = ...): List<Campaign> {
    return _campaigns.value.filter { campaign ->
        campaign.campaignType == campaignType &&
        campaign.id != null &&
        !disabledIds.contains(campaign.id) &&
        TriggerEventMatcher.shouldShowCampaign(
            triggerEvent = campaign.triggerEvent,
            campaignId = campaign.id,
            trackedEvents = _trackedEvents.value
        )
    }
}

private fun handleDeepLinkIntent(intent: Intent?) {
    if (intent?.action == Intent.ACTION_VIEW) {
        val screenName = intent.data?.host?.lowercase()  // "appstorys://TestScreen" → "testscreen"
        if (!screenName.isNullOrEmpty()) routeScreen(screenName)
    }
}

private fun routeScreen(screenName: String) {
    when (screenName.lowercase()) {
        "xmlhome" -> startActivity(Intent(this, TestActivity::class.java))
        "cashbook" -> startActivity(Intent(this, MoreActivity::class.java))
        else -> {
            // Compose screen — emit to StateFlow, LaunchedEffect handles it
            (applicationContext as App).navigateToScreen(screenName)
        }
    }
}

overlayElements() is the Android SDK's equivalent of Flutter's Stack approach. It renders all floating/overlay campaign types in a single composable placed outside the NavHost — so they appear above every screen.

If overlayElements() were inside a specific route, it would disappear during navigation transitions. Placing it in the root Box means the Floater, Modal, CSAT, etc. remain visible regardless of which screen is active.

Section 21

Cross-Platform Design Decisions

DecisionWhy
Single AppStorysCore for all platforms All HTTP logic, state management, variant resolution, trigger matching lives once — zero divergence. Android, Flutter, and RN are all guaranteed identical behavior.
StateFlow as the source of truth Replay semantics mean no widget ever misses a campaign update — late subscribers still get the current value. Eliminates timing races across all three platforms.
Variants resolved before emission Android reads typed Kotlin objects. Flutter/RN read JSON. Neither needs to implement variant resolution logic — core does it once for everyone.
ETag CDN caching Campaigns.json is often hundreds of KB. After first download, 304 responses skip re-download completely — making every subsequent getScreenCampaigns() call much faster.
expect/actual for PlatformStorage Common code never imports android.* or NSUserDefaults. The KMP compiler links the correct platform implementation — the core is truly portable.
JSON bridge methods (getCampaignsJson etc.) Flutter/RN can't consume Kotlin objects — they need strings. Bridge methods serialize state on demand. Android never uses them (reads StateFlow directly).
SupervisorJob in coroutine scopes If the campaigns fetch fails, the entire SDK doesn't crash. Other coroutines (event tracking, user properties) remain alive and operational.
ApiResult sealed class Every API call returns Success or Error — no exceptions thrown across call boundaries. Core code handles both cases explicitly, no silent failures.
getFilteredCampaigns() checks 3 conditions Campaign must: (1) match campaign type, (2) not be in disabled list, (3) pass TriggerEventMatcher. All composables/widgets go through this — consistent filtering everywhere.
navigateToScreen callback in initialize() The SDK must trigger app navigation when a campaign CTA is tapped, but it can't import NavController or know the app's routing scheme. The callback inverts control — the app decides how to handle it.
