Section 02

The Bridge — MethodChannel & EventChannel

Two types of channels connect Dart and Kotlin. They solve different problems.

MethodChannel

Request / Response

Flutter sends a named call with arguments. Kotlin handles it, resolves or rejects back. Like an HTTP API call — one request, one response, then done.

Used for: initialize, getScreenCampaigns, trackEvent, dismissCampaign

EventChannel

Continuous Push

Kotlin pushes data to Flutter whenever it wants. Flutter just listens. No request needed. Like a WebSocket — the server sends when ready.

Used for: campaigns stream — pushes JSON on every StateFlow update

METHODCHANNEL (Request → Response)
Flutter: invokeMethod('initialize', {appId, accountId, userId})
                    ↓ crosses runtime boundary ↓
Kotlin:  handleInitialize() → core.initialize() → result.success(null)
                    ↓ back to Dart ↓
Flutter: Future resolves ✓

EVENTCHANNEL (Kotlin pushes, Flutter listens forever)
Kotlin:  core.campaigns.collect { _ →
             sink.success(core.getCampaignsJson())   // push on every change
         }
                    ↓ streams to Dart ↓
Flutter: campaignsStream.listen((json) { ... })      // receives every push
Layer 01

A KMP (Kotlin Multiplatform) library published to JitPack. It owns all business logic — HTTP calls, campaign state, user tracking. Flutter never touches the network directly.

Layer 02 — Kotlin Side

AppstorysFlutterPlugin.kt — The Android Bridge

This is the Android entry point. Flutter auto-registers it via the plugin manifest. It sets up both channels and delegates everything to AppStorysCore.

MethodChannel Setup

AppstorysFlutterPlugin.kt
class AppstorysFlutterPlugin : FlutterPlugin, MethodCallHandler {

    private val core: AppStorysCore by lazy { AppStorysCore(PlatformStorage()) }

    // Coroutine scope — SupervisorJob means one failure doesn't kill others
    private val pluginScope = CoroutineScope(SupervisorJob() + Dispatchers.Default)

    override fun onAttachedToEngine(binding: FlutterPlugin.FlutterPluginBinding) {
        // Channel name must match exactly what Dart uses
        channel = MethodChannel(binding.binaryMessenger, "appstorys_flutter")
        channel.setMethodCallHandler(this)
        // ... EventChannel setup (see below)
    }

    override fun onMethodCall(call: MethodCall, result: Result) {
        when (call.method) {
            "initialize"          -> handleInitialize(call, result)
            "getScreenCampaigns"  -> handleGetScreenCampaigns(call, result)
            "trackEvent"          -> handleTrackEvent(call, result)
            "dismissCampaign"     -> handleDismissCampaign(call, result)
            // ... 13 more methods
            else -> result.notImplemented()
        }
    }

    // Every handler uses this — converts exceptions to PlatformException
    private fun runBridgeCall(result: Result, block: () -> Any?) {
        try {
            result.success(block())
        } catch (e: Exception) {
            result.error("APPSTORYS_ERROR", e.message, null)
        }
    }

    private fun handleGetScreenCampaigns(call: MethodCall, result: Result) {
        val screenName = call.argument<String>("screenName")
        runBridgeCall(result) {
            core.getScreenCampaigns(screenName = screenName!!, positionList = positionList)
            null   // void → Dart Future resolves with null
        }
    }

    // Lifecycle — cancel everything when Flutter engine detaches
    override fun onDetachedFromEngine(binding: FlutterPlugin.FlutterPluginBinding) {
        channel.setMethodCallHandler(null)
        campaignsCollectionJob?.cancel()
        pluginScope.cancel()
    }
}

EventChannel Setup — The Campaign Push

🔑
This is the most important piece

The EventChannel collects AppStorysCore's StateFlow and pushes JSON to Dart on every emission. This is why widgets update instantly without polling.

campaignsEventChannel = EventChannel(
    binding.binaryMessenger,
    "appstorys_flutter/campaigns_stream"  // ← must match Dart
)

campaignsEventChannel.setStreamHandler(object : EventChannel.StreamHandler {

    override fun onListen(arguments: Any?, sink: EventChannel.EventSink) {
        campaignsCollectionJob?.cancel()
        campaignsCollectionJob = pluginScope.launch {

            // StateFlow.collect() — stays alive, fires on every campaign update.
            // StateFlow semantics: replays current value immediately to new collectors.
            core.campaigns.collect { _ ->
                val json = core.getCampaignsJson()

                // Must switch to Main thread — EventSink.success() requires it
                withContext(Dispatchers.Main) {
                    sink.success(json)   // ← pushes JSON string to Dart
                }
            }
        }
    }

    override fun onCancel(arguments: Any?) {
        campaignsCollectionJob?.cancel()   // Flutter unsubscribed — stop collecting
    }
})

Platform Interface — The Abstract Contract

Defines what every platform implementation must provide. The actual implementation is swapped via the instance setter.

appstorys_flutter_platform_interface.dart
abstract class AppstorysFlutterPlatform extends PlatformInterface {

    // Token prevents unauthorized swapping of the instance
    static final Object _token = Object();

    // Default → MethodChannel (Android/iOS)
    // Can be replaced for web or testing
    static AppstorysFlutterPlatform _instance = MethodChannelAppstorysFlutter();

    static set instance(AppstorysFlutterPlatform instance) {
        PlatformInterface.verifyToken(instance, _token);  // security check
        _instance = instance;
    }

    // Every method throws by default — concrete impl must override
    Stream<String> get campaignsStream {
        throw UnimplementedError('campaignsStream has not been implemented.');
    }

    Future<void> initialize({...}) {
        throw UnimplementedError('initialize() has not been implemented.');
    }
    // ... 13 more methods
}

Layer 02 — Dart Side

MethodChannelAppstorysFlutter — Dart Bridge

The Dart half of the bridge. Translates method calls into platform messages that cross the Dart/Kotlin runtime boundary.

appstorys_flutter_method_channel.dart
class MethodChannelAppstorysFlutter extends AppstorysFlutterPlatform {

    // Channel names must match Kotlin exactly
    final methodChannel = const MethodChannel('appstorys_flutter');
    static const EventChannel _campaignsEventChannel =
        EventChannel('appstorys_flutter/campaigns_stream');

    // EventChannel → Dart Stream<String>
    @override
    Stream<String> get campaignsStream {
        // receiveBroadcastStream() creates a NEW native listener each call.
        // This is why AppstorysFlutter caches it — to prevent duplicate listeners.
        return _campaignsEventChannel
            .receiveBroadcastStream()
            .map((event) => event as String);
    }

    // Each method: invoke named string + Map → await → return typed result
    @override
    Future<void> getScreenCampaigns({required String screenName, ...}) async {
        try {
            await methodChannel.invokeMethod<void>(
                'getScreenCampaigns',                    // matches Kotlin when() case
                {'screenName': screenName, ...},         // Map → Kotlin Bundle
            );
        } on PlatformException catch (error) {
            throw AppstorysException.fromPlatformException(error);
        }
    }
}
Layer 04

AppstorysFlutter — The Public API

This is what the client app imports. It adds validation and the broadcast stream cache on top of the raw channel calls. The client never touches layers below this.

appstorys_flutter.dart
class AppstorysFlutter {

    // ─── Stream cache ────────────────────────────────────────────────────────
    // receiveBroadcastStream() creates a new native listener every call.
    // We cache once so Banner + Floater + any future widget all share ONE listener.
    Stream<String>? _campaignsStreamCache;

    Stream<String> get campaignsStream {
        _campaignsStreamCache ??=
            AppstorysFlutterPlatform.instance.campaignsStream
                .asBroadcastStream();   // ← allows multiple simultaneous listeners
        return _campaignsStreamCache!;
    }

    // ─── Validation before delegation ────────────────────────────────────────
    Future<void> initialize({required String appId, required String accountId, String? userId}) {
        _requireNonBlank(appId, 'appId');
        _requireNonBlank(accountId, 'accountId');
        if (userId != null && userId.trim().isEmpty)
            throw ArgumentError.value(userId, 'userId', 'userId cannot be blank.');

        return AppstorysFlutterPlatform.instance.initialize(
            appId: appId.trim(),
            accountId: accountId.trim(),
            userId: userId?.trim(),
        );
    }

    Future<void> trackEvent({required String event, String? campaignId, Map<String, Object?>? metadata}) {
        _requireNonBlank(event, 'event');
        _validateMetadata(metadata);   // recursive — checks nested Lists and Maps too
        return AppstorysFlutterPlatform.instance.trackEvent(
            event: event.trim(),
            campaignId: campaignId?.trim(),
            metadata: metadata,
        );
    }

    // Throws ArgumentError for blank values
    void _requireNonBlank(String value, String name) {
        if (value.trim().isEmpty)
            throw ArgumentError.value(value, name, '$name cannot be blank.');
    }
}
⚡
Why asBroadcastStream() matters

A standard Dart stream allows only one listener. Without asBroadcastStream(), the second widget to subscribe (e.g. Floater after Banner) throws "Bad state: Stream already has a listener". The broadcast version allows unlimited simultaneous listeners on one native EventChannel.

The Stream Pipeline

This pipeline is the core of the reactive architecture. It connects AppStorysCore's internal state all the way to widget renders — with zero polling.

Section 09

CampaignsStreamMixin

Every campaign widget needs the same lifecycle wiring — subscribe on init, cancel on dispose. The mixin eliminates this boilerplate.

lib/src/utils/campaigns_stream_mixin.dart
mixin CampaignsStreamMixin<T extends StatefulWidget> on State<T> {
    StreamSubscription<String>? _campaignsSub;

    void subscribeToCampaigns(
        Stream<String> stream,
        void Function(String json) onUpdate, {
        void Function()? onError,       // optional — Banner uses it, Floater doesn't
    }) {
        _campaignsSub = stream.listen(
            onUpdate,
            onError: (Object _) => onError?.call(),
        );
    }

    @override
    void dispose() {
        _campaignsSub?.cancel();    // always cancels — prevents setState after unmount
        super.dispose();
    }
}

Before vs After:

// ❌ BEFORE — copy-pasted boilerplate in every widget
class _SomeCampaignState extends State<SomeCampaign> {

    @override

            _onCampaignsUpdate,

// ✅ AFTER — 1 line, mixin handles the rest

class _AppStorysBannerState extends State<AppStorysBanner>
    with CampaignsStreamMixin {

    BannerCampaign? _currentBanner;
    bool _showBanner = true;   // false once user taps the close button
    bool _isLoading = true;    // true until first stream emission arrives

    @override
    void initState() {
        super.initState();
        subscribeToCampaigns(
            widget.appStorys.campaignsStream,
            _onCampaignsUpdate,
            onError: () { if (mounted) setState(() => _isLoading = false); },
        );
    }

    void _onCampaignsUpdate(String json) {
        final all = jsonDecode(json) as List;

        // Stream carries ALL campaign types — filter for BAN only
        final banners = all
            .whereType<Map>()
            .where((c) => c['campaign_type'] == 'BAN')
            .toList();

        if (banners.isEmpty) {
            // Screen changed with no banner — clear and reset _showBanner
            // so it reappears if user navigates back
            setState(() { _currentBanner = null; _showBanner = true; _isLoading = false; });
            return;
        }

        // Flatten: details map + variant + campaign-level id
        final normalized = { ...details, ...firstVariant, 'id': rawCampaign['id'] };
        final banner = BannerCampaign.fromJson(normalized);

        setState(() { _currentBanner = banner; _isLoading = false; });
        widget.appStorys.trackEvent(event: 'viewed', campaignId: banner.id);
    }

    @override
    Widget build(BuildContext context) {
        // Guard — invisible until a campaign is ready and not dismissed
        if (!_showBanner || _currentBanner == null || _isLoading)
            return const SizedBox.shrink();

        // Renders:
        // - NetworkImage with responsive aspect-ratio height
        // - Border radius from campaign styling
        // - Cross button (if enabled) positioned via CrossButtonMargin
        // - Tapping tracks 'clicked' event
    }
}

lib/src/widgets/app_storys_floater.dart
class _AppStorysFloaterState extends State<AppStorysFloater>
    with CampaignsStreamMixin {

    FloaterCampaign? _floater;
    bool _visible = false;

    void _onCampaignsUpdate(String json) {
        final fltCampaigns = all
            .whereType<Map>()
            .where((c) => c['campaign_type'] == 'FLT')
            .toList();

        if (fltCampaigns.isEmpty) {
            setState(() { _floater = null; _visible = false; });
            return;
        }

        // Merge details + id (id lives outside details in raw JSON)
        final normalized = { ...details, 'id': raw['id'] };
        final floater = FloaterCampaign.fromJson(normalized);

        setState(() { _floater = floater; _visible = true; });
        widget.appStorys.trackEvent(event: 'viewed', campaignId: floater.id);
    }

    @override
    Widget build(BuildContext context) {
        if (!_visible || _floater == null) return const SizedBox.shrink();

        return Align(
            // position from dashboard config: "left" or "right"
            alignment: isLeft ? Alignment.bottomLeft : Alignment.bottomRight,
            child: Padding(
                padding: EdgeInsets.only(
                    bottom: s?.marginBottom ?? 0,
                    left:   isLeft ? (s?.marginLeft ?? 0)  : 0,
                    right:  isLeft ? 0 : (s?.marginRight ?? 0),
                ),
                child: GestureDetector(
                    onTap: _onTap,    // tracks 'clicked', calls widget.onTap(link)
                    child: Image.network(floater.image!),
                ),
            ),
        );
    }

    void _onTap() {
        widget.appStorys.trackEvent(event: 'clicked', campaignId: _floater!.id);
        // Navigation is host app's responsibility — SDK never controls routing
        if (link != null && widget.onTap != null) widget.onTap!(link!);
    }
}
Section 11

Models Layer

Each campaign type has its own model. The pattern is always: extract details map → merge campaign-level id → Model.fromJson(normalized).

⚠️
KMP Serialization Quirk

FloaterStyling — all numeric fields are declared as String? in KMP, not Int? or Double?. Direct cast to num throws at runtime. Always use safe parsing.

lib/src/models/floater_models.dart — safe numeric parsing
factory FloaterStyling.fromJson(Map<String, dynamic> json) {
    // KMP sends all values as String? — handle both String and num defensively
    double v(String key) {
        final val = json[key];
        if (val == null) return 0;
        if (val is num) return val.toDouble();
        return double.tryParse(val.toString()) ?? 0;  // safe parse
    }

    return FloaterStyling(
        topLeftRadius:     v('topLeftRadius'),
        topRightRadius:    v('topRightRadius'),
        bottomLeftRadius:  v('bottomLeftRadius'),
        bottomRightRadius: v('bottomRightRadius'),
        // ⚠️ KMP field names differ from dashboard JSON keys
        marginBottom: v('floaterBottomPadding'),   // NOT 'marginBottom'
        marginLeft:   v('floaterLeftPadding'),      // NOT 'marginLeft'
        marginRight:  v('floaterRightPadding'),     // NOT 'marginRight'
    );
}

The id lives outside the details map in the raw campaign JSON. It must be explicitly merged:

// Raw JSON structure from the stream:
// {
//   "id": "abc-123",           ← top-level
//   "campaign_type": "FLT",
//   "details": {               ← everything else lives here
//     "image": "...",
//     "link": "...",
//     "styling": { ... }
//   }
// }

final normalized = <String, dynamic>{
    ...details,                                        // spread details
    'id': (raw['id'] ?? details['id'])?.toString(),   // lift id into same map
};

                    └─ StateFlow emits again
                            │
                            ├─ Banner: no BAN → stays hidden
                            │
                            └─ Floater: FLT found
                                       → parse FloaterCampaign
                                       → trackEvent('viewed')
                                       → setState _visible = true
                                       → renders at bottom corner
Section 15

Key Design Decisions

Decision Why
EventChannel over polling Campaigns appear the instant core's StateFlow fires — no fixed wait, no missed updates, no wasted HTTP calls
Single broadcast stream One native listener, unlimited Dart subscribers without duplication or extra EventChannels
asBroadcastStream() cached receiveBroadcastStream() creates a new native listener each call — caching prevents duplicate listeners
StateFlow replay on subscribe Widgets get current campaigns immediately on mount, even if getScreenCampaigns() completed before they built
Filtering in widget, not core One stream carries all types — each widget self-selects its type. Simpler than multiple EventChannels per campaign type
CampaignsStreamMixin Subscription lifecycle is identical across all campaign widgets — extracted once, zero copy-paste for every future type
Validation in AppstorysFlutter, not MethodChannel Keep the bridge thin. All business rules live in Dart before any cross-runtime call
Navigation via onTap callback SDK never controls routing — the host app owns its navigator, deep links, and internal routes
Platform Interface abstraction Enables mock implementations for unit testing without native code or a real device
SupervisorJob in pluginScope One failed coroutine (e.g. a single event send) doesn't cancel the entire plugin scope and kill all other operations
